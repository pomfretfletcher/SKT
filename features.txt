Skill tree is not drawn nor updated when in any godot screen/tab except 2D. This allows
	logic issues to not happen when working on a tool script that may have been being
	currently run. This is done through the custom Skill Tree Pauser plugin within addons
	folder.


Interaction with SKT Software without custom implementation:
	Most Interaction will be within the deligated Frontend and within the Skill Tree Controls
		themselves (The SkillNodes, SkillBranches and BranchFollowPoints). The rest of the nodes
		within SKT Main are responsible for the Backend processing of the SKT Skill Trees, which
		means that users can ignore them for basic use.
	
	The main interactions the user will need to complete for creating a skill tree are:
		Spawning SkillNodes, connecting SkillNodes with SkillBranches
		Positioning SkillNodes on the screen, and altering the path of SkillBranches with
			BranchFollowPoints
		Deciding whether they are using the progression tier system, and assigning tiers to 
			SkillNodes if they are
		Deciding whether they are using the upgrade cost system, and assigning upgrade costs to
			SkillNodes if they are
		Saving and Loading their skill tree data
		Assigning Unlock Types (the way SkillNodes are upgraded) and Unlock Conditions (the way
			a SkillBranch between two SkillNodes tell whether the end node of the SkillBranch can be
			upgraded)
		Assigning data to hold in SkillNodes
		

Text Formats
"if node != null:" [instead of "if node:"]
"if node == null:" [instead of "if !node"]
"if not _setup" [instead of "if !_setup", do this for states of a process for example]
"if !xxx:" is never used in SKT Code
"_setup or _updating" for boolean states
